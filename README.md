# analesthetics

把「这张画好不好」拆成可以测量的量：**先出读数，再让模型解释读数。**

> 名字取自 analysis + aesthetics。

---

## 为什么

直接问多模态模型「这张画怎么样」，通常得到一段听起来合理、但与画面无关的评价。
判断无法被检验，也无法被复现。

analesthetics 的做法是把评价拆成两层：

```
测量   计算机视觉提取几十项读数          ← 可复现
解释   多模态模型把读数翻译成人话         ← 只能引用读数，不能编造观察
```

算法负责出数，模型负责解释。**结论至少是可追溯的。**

---

## 它测什么

一张图跑出 **23 项指标**，分六个维度：

| 维度 | 项数 | 测的内容 |
|---|---|---|
| `silhouette` | 8 | 轮廓实心度、顶点归一化、周长、曲率分布、形状完整度 |
| `balance` | 5 | 画面重心偏移、左右与上下的视觉重量比 |
| `color` | 4 | 主色/次色/点缀色占比、色相与饱和度分布 |
| `density` | 3 | 疏密三档占比、密度熵 |
| `texture` | 2 | 高频能量、边缘密度 |
| `symmetry` | 1 | 对称残差 |

每条读数都是一个结构化观测，自带出处：

```json
{"key": "silhouette.solidity", "value": 0.9606, "unit": "ratio",
 "region": [313, 0, 800, 442], "conf": 1.0, "method": "cv2.convexHull/v1"}
```

`region` 把数字钉到画面上的具体区域，`method` 说明它是怎么算出来的 ——
**这两个字段是「可解释」的全部来源**：任何一个读数都能回答「算的哪块、怎么算的」。

所有指标在**短边归一化到 768** 后计算。跨作品比较必须在同一尺度下，
否则分辨率会变成一个隐藏变量。

## 用法

```bash
pip install -e .

# 单张图出全部读数（JSON）
python -m analesthetics.cli path/to/image.png

# 或在代码里
from analesthetics import analyze
result = analyze("image.png")
print(result.to_dict())
```

## 和参考分布比

读数本身没有好坏 —— **一个数字只有在和有水平的参照比的时候才有意义。**

建议做法：先跑一批公认好的作品建立分布，再拿待测作品去比。
本仓库不带参考集（数据集版权问题），但接口支持你把分布算出来。

## 已知局限

- **不判内容对错**。型准、透视、结构问题需要另外的方法（MLLM 或人工）。
- **不看图层**。只支持单图层扁平图像；带图层信息的分层文件需要先合并。
- **对风格敏感**。写实、厚涂、平涂、线稿的读数分布差异很大，参考集要和目标同一风格。
- **6:3:1 是经验先验，不是硬判据**。它来自对好画师作品分布的观察，不是美学定律。
- **分辨率必须归一化**。实测：图片尺寸归一化会让部分指标的区分力从 AUC 0.922 降到 0.848，
  所以不同尺寸的图直接比会得到假差异。
